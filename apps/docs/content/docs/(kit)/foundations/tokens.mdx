Every color, radius, space, size, shadow and motion value in the kit is a `--cui-*` CSS custom property. Kit components read only these properties, so changing one changes every component that uses it. The kit defines 129 of them.

<SolidDemo name="tokens/usage" />

The card above reads four tokens with `var()`. The button reads the same tokens through its own styles.

## How a name is built

A name is `--cui-` followed by the token path in kebab case. The path `surface.menuHover` becomes `--cui-surface-menu-hover`. A half step uses a hyphen, so `space.1.5` becomes `--cui-space-1-5`.

The CSS name is the stable public API. In TypeScript, the [`tokens`](/docs/utilities/token-exports#tokens) export holds the same paths, and each leaf is a `var(--cui-…)` string.

Each mode sets every token. Most color tokens differ between dark and light, and `data-cui-theme` picks the mode. [Theming](/docs/theming) covers the attribute and overrides.

The design rules for each role live in Inkstone: [Colour](/docs/design/color), [Typography](/docs/design/typography), [Space and shape](/docs/design/space-and-shape) and [Motion](/docs/design/motion). This page lists the values.

## Read the tables

Each group has a live table and a static table. The live table reads every value from your browser with `getComputedStyle`, inside a `data-cui-theme="dark"` scope and a `data-cui-theme="light"` scope. It shows what the kit really ships. The static table lists the values in `packages/kit/src/foundation/theme-values.ts`, the one registry that both modes come from. Agents and the Markdown route read the static table.

`pnpm --filter @codeui/kit test` checks every name and value against `docs/kit-2026/design/k5-token-map.json`.

The kit does not load a font file. Without Inter, the stack falls back to the system font. [Typography and spacing](/docs/foundations/typography-and-spacing) shows the scale in use.
