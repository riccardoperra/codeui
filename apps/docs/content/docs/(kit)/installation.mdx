## Requirements

The component package supports Solid `^1.9.8`. Its styles are plain CSS. The library builds the Inkstone theme from DTCG tokens before publishing.

## Install

```sh
pnpm add @codeui/kit solid-js@^1.9.8
pnpm add -D vite vite-plugin-solid
```

## Configure Vite

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import solid from "vite-plugin-solid";

export default defineConfig({
	plugins: [solid()],
});
```

## Automatic styles

Import a Solid component normally. Its module imports the compiled component stylesheet, shared styles and theme.

```ts title="App.tsx"
import { Button } from "@codeui/kit";
```

No manual CSS import is required. With production tree shaking, unused component modules and their CSS can be removed. All variants and runtime states of an included component remain available. The library does not purge individual selectors.

Import ready components from `@codeui/kit` or a component entry such as `@codeui/kit/button`. Import styled parts from the component’s `/parts` entry. See [Ready or parts](/docs/ready-or-parts).

## Pick a theme

Set `data-cui-theme="dark"` or `data-cui-theme="light"` on the document's `html` element. Portalled content then inherits the page theme too. Without an explicit attribute, the theme follows the system color scheme.

See [Theming](/docs/foundations/theming) for plain CSS overrides. Applications that author their own vanilla-extract styles still configure their own plugin for those files. The kit does not require it.

## CSS without Solid

Install only `@codeui/styles` to use the compiled CSS in HTML or another rendering system. It does not require a framework runtime. Load `theme.css` and the component files through your bundler or ordinary stylesheet links.

The CSS provides appearance and state styling. The caller supplies markup, accessible names and behavior. Focus management, positioning, keyboard navigation, gestures and virtualized lists belong to the Solid components.

## Inkstone tokens

Install `@codeui/inkstone` to use the theme in your own UI. Load `@codeui/inkstone/theme.css` for the CSS custom properties. Import `tokens`, `themeValues`, and `breakpoints` from the package entry, or use the resolved light and dark JSON in other tools. [Token generation](/docs/foundations/token-generation) describes the outputs.

## Server rendering

Use the package's `solid` condition with Solid's server compiler, as the fixture does through `solid({ ssr: true })`. Dialog, Popover, Sheet and CommandMenu include their open content in server HTML. Hydration adopts those nodes and moves them to the portal target. Closed content stays absent unless force-mounted.

The packed-consumer SSR and hydration checks are documented in `docs/kit-2026/consumer.md` and `examples/` in the repository.
