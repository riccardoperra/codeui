This page is for coding agents that generate UI with `@codeui/kit`. It lists the import paths, the rules generated code must follow, and every component with its main props. Each component name links to its full page.

## Import map

| Import from | What it holds | Use it for |
| --- | --- | --- |
| `@codeui/kit` | Every ready component, the option helpers, field helpers, `icons`, `SvgIcon`, `mergeClasses`, and the token objects | Almost everything |
| `@codeui/kit/<name>` | The ready component and its public types and helpers | Import a single component |
| `@codeui/kit/<name>/parts` | The styled parts of one component, its part name map, and its style functions | A layout the ready component cannot give |
| `@codeui/kit/tokens` | `tokens`, `themeVars`, `themeTokens`, `layoutVars`, `breakpoints`, `responsiveStyle`. No component. | vanilla-extract `.css.ts` files, which run in Node |

See [Ready or parts](/docs/ready-or-parts) for supported component entry points.

Import parts as a namespace:

```tsx
import * as D from "@codeui/kit/dialog/parts";
```

The app needs `solid-js ^1.9.8` and the vanilla-extract Vite plugin. See [Installation](/docs/installation).

## Rules for generated code

<SolidDemo name="agents/export-panel" />

```css title="export-panel.css"
/* App CSS reads only --cui-* tokens, and stays unlayered so it wins over the kit. */
.export-panel {
	background: var(--cui-surface-panel);
	border-radius: var(--cui-radius-card);
	padding: var(--cui-space-4);
	max-width: 360px;
}
```

Follow every rule. A reviewer rejects code that breaks one.

1. **Use a ready component first.** Compose parts only when the ready component cannot give the layout. [Ready or parts](/docs/ready-or-parts) explains the choice.
2. **Read values from tokens.** Write colors, radii, spacing, font sizes, shadows, and durations as `var(--cui-…)` in CSS, or as `tokens.…` in TypeScript. Never write a hex color, a pixel radius, or a pixel gap for UI chrome. Artwork the user creates is the only exception. [Tokens](/docs/foundations/tokens) lists every name.
3. **Lay out with `Stack`.** Set `gap` to a spacing key, such as `"2"` or `"4"`. Do not write margins between siblings.
4. **Set text with `Text`.** Set the element with `as` and the size with `size`. A heading level never comes from the size.
5. **Style an inner part with `classes` or `data-cui`.** Pass `classes={{ trigger: "…" }}` on the ready component, or select `[data-cui="select-trigger"]` in app CSS. Copy part names from the Anatomy table of the component page. Never guess them from export names.
6. **Write app CSS without a layer.** Kit rules sit in `@layer cui`, so unlayered app CSS wins without `!important`. Put a CSS reset in a layer declared before `cui`. See [Cascade layers](/docs/foundations/cascade-layers).
7. **Theme with `data-cui-theme`.** Set `"dark"` or `"light"` on `<html>`. Remove the attribute to follow the system. The kit has no theme provider and no `system` value.
8. **Name every control.** Give each field a `label`, or an `aria-label` when no visible label fits. Give each `IconButton` an `aria-label`. Give each `Spinner` a `label`.
9. **Keep the keyboard working.** Do not put a click handler on a `div`. Use `Button`, `Link`, or a radio or checkbox component. Do not stop Escape from reaching an overlay.
10. **Use the controlled pattern.** See [Controlled state](#controlled-state).

## Controlled state

Every stateful component follows Kobalte's pattern. Pass the uncontrolled default, or the value and its change handler together.

| State | Uncontrolled | Controlled |
| --- | --- | --- |
| Value | `defaultValue` | `value` and `onChange` |
| Checked | `defaultChecked` | `checked` and `onChange` |
| Open | `defaultOpen` | `open` and `onOpenChange` |

- `Select` calls `onChange` with `null` when the selection clears. Guard it: `onChange={value => value && setFont(value)}`.
- `NumberField` uses `null` for an empty field.
- `Slider` calls `onChange` while the thumb moves and `onChangeEnd` once on release.
- `Pagination` takes `page` and `onChange`, starting at 1.
- `CommandMenu` has no uncontrolled mode. Pass `open` and `onOpenChange`.

## Fields

`TextField`, `TextArea`, `NumberField`, `Select`, `Combobox`, `Checkbox`, `RadioList`, `Switch`, `Slider`, and `OptionCardGroup` take `label`, `description`, and `errorMessage`. The kit links the label and the messages to the input.

- On the text fields and `Select`, `errorMessage` shows only while `validationState="invalid"`. The kit runs no validation of its own.
- `Select` requires `aria-label` in its type, even when it has a `label`.
- To build a custom field, use the helpers in [Field helpers](/docs/utilities/field-helpers).
- To build options from objects, use `createSelectOptions`, `createComboboxOptions`, `createOptionCardItems`, or `createAccordionItems`. See [Options and collections](/docs/utilities/options-and-collections).

## Toasts and SSR

Create the toast controller inside a component, as `ExportPanel` does above, or in the app root. A controller in a module is shared by every request on a server. Render one `Toaster` for each controller, inside the app's providers. [Show notifications](/docs/patterns/show-notifications) shows the setup.

On the server, `show` and `promise` do nothing. Toasts render only on the client.

Portalled content renders only on the client. That covers the bodies of `Dialog`, `Sheet`, `Popover`, `DropdownMenu`, `Tooltip`, `Select` lists, `Combobox` lists, and `CommandMenu`. Do not put content a crawler must read inside one.

## What does not exist

Do not generate code that uses these. Each one fails to compile or to resolve.

- `@codeui/kit/theme.css`. Solid components import their CSS and theme automatically. CSS-only consumers import `@codeui/styles/theme.css` and component CSS files, or `@codeui/styles/all.css`.
- A theme provider, or `data-cui-theme="system"`.
- `Box`, `HStack`, `VStack`, or sprinkles props such as `padding` or `marginTop`. Use `Stack` and a class.
- `asChild`. Kobalte and the kit use `as` for polymorphism.
- A re-export of Kobalte's `toaster`. Import it from `@kobalte/core/toast` when you compose toast parts.
- `toast.remove` or `toast.custom`. Use `dismiss`, or compose the toast parts.
- A `Meter`, `ContextMenu`, `HoverCard`, `DatePicker`, or `ColorPicker` component.
- Subpaths for components outside the list in [Import map](#import-map).
