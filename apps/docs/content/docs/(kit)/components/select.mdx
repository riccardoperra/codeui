## When to use

Use `Select` when the user picks from a list of options they know by name, such as the editor font, the export format, or the pixel ratio. The list fits on screen without search.

## When to choose another component

| Component | Use it when | The deciding difference |
| --- | --- | --- |
| `Select` | The user picks one or more values from a short list. | A button opens a list. No typing. |
| [Combobox](/docs/components/combobox) | The list is long enough that the user wants to search it. | A text input filters the list as the user types. |
| [Listbox](/docs/components/listbox) | The options stay visible on the page, such as a sidebar list. | No trigger and no popover. |
| [CommandMenu](/docs/components/command-menu) | The user runs an action, such as Export as PNG. | A dialog that runs a command and keeps no value. |
| [SegmentedControl](/docs/components/segmented-control) | There are two to four short options. | All options are visible at once. |

Inkstone puts Select after segmented controls, switches, and option cards. Inside a modal dialog, prefer those controls over Select. See [Choosing a control](/docs/design/patterns).

The label, description, and error message render only when you pass them. The list renders in a portal on `document.body` while it is open. With `name`, `Select` also renders one `input type="hidden"` for each selected value, with no `data-cui` marker and no `classes` key. See [Submit with a form](#submit-with-a-form).

## Variants

### String options

The [live demo](#live-demo) passes a `string[]`. A `string[]` works as it is. Each string is the value, the label, and the type-ahead text.

### Object options with `createSelectOptions`

<SolidDemo name="select/object-options" />

`createSelectOptions` maps your objects to `{ label, value }` options. Spread `props()` for the keys and renderers. Spread `controlled(value, setValue)` to keep your own value, here the theme id, instead of the option object. See [Options and collections](/docs/utilities/options-and-collections) for the full return value.

### Object options without the helper

<SolidDemo name="select/raw-objects" />

Without the helper, set `optionValue` and `optionTextValue`, and pass `itemLabel` and `valueComponent`. `Select` renders the raw option when you leave out the two renderers. An object then renders as nothing useful.

### Disabled options

<SolidDemo name="select/disabled-options" />

`optionDisabled` takes a key or a function. Disabled options stay in the list, take no selection, and are skipped by the arrow keys. `createSelectOptions` has no disabled mapping. With the helper, pass `optionDisabled` as a function over the `{ label, value }` option.

### Themes

<SolidDemo name="select/themes" />

`filled`, the default, draws the field box. `inline` drops the box and keeps a bottom border, for a select that sits inside a sentence or a toolbar.

### Sizes

<SolidDemo name="select/sizes" />

`xs`, `sm`, `md`, and `lg` are 28px, 36px, 44px, and 52px at comfortable density. The default is `sm`. Density adjusts the height without changing the font size.

### Multiple selection

<SolidDemo name="select/multiple" />

`multiple` makes `value`, `defaultValue`, and `onChange` work with arrays. The list stays open after each pick. The trigger joins the selected strings with ", ". Pass `valueComponentMultiple` for object options or for a summary such as a count. Pass the option type explicitly, as in `<Select<string> multiple …>`. Without it, TypeScript infers the option type from the array value.

### Description

<SolidDemo name="select/description" />

`description` renders a hint under the trigger and links it as the accessible description.

## States

### Controlled and uncontrolled

<SolidDemo name="select/uncontrolled" />

Pass `value` and `onChange` to own the value, as the [live demo](#live-demo) does. Pass `defaultValue` to let `Select` keep it. `onChange` receives `null` when the selection is cleared. Guard for it before you write the value back, as in `value => value && setFont(value)`.

### Disabled

<SolidDemo name="select/disabled" />

`disabled` disables the trigger and removes it from the tab order.

### Read only

<SolidDemo name="select/read-only" />

`readOnly` keeps the trigger focusable and blocks changes. Use it for a value the user can see but someone else sets.

### Invalid and required

<SolidDemo name="select/invalid" />

`validationState="invalid"` marks the trigger with `aria-invalid` and shows `errorMessage`. `required` marks the field as required for assistive technology. `Select` does not validate on its own. Set `validationState` from your form logic.

### Empty

<SolidDemo name="select/empty" />

`Select` has no empty-state prop. With no options, the list opens with nothing in it. Disable the trigger and explain why in the placeholder or the description, as the demo does.

### Style the list popover with `classes`

<SolidDemo name="select/classes" />

`classes` puts a class on any part in the anatomy table. `classes.content` reaches the portalled list, so you can size or position it without a global selector. The kit classes come first and your class comes after, so your rules win at equal specificity. `slotClasses` is deprecated. Its `input`, `errorLabel`, and `itemValue` keys map to `trigger`, `errorMessage`, and `value`.

### Submit with a form

<SolidDemo name="select/form" />

With `name`, `Select` renders one `input type="hidden"` for each selected value, so the form submits the value under that name. The submitted value is the option key, which is `optionValue` converted to a string. For string options, that is the string. With `multiple`, each selected value submits under the same name. With nothing selected, or when the select is disabled, the form submits nothing for that name. Hidden inputs take no part in native validation, so check `required` before you submit.

## Styled parts API

Import the ready `Select` and `createSelectOptions` from `@codeui/kit/select`. To change the structure, import the parts from `@codeui/kit/select/parts`.

```tsx
import * as S from "@codeui/kit/select/parts";

<S.Root
	options={["PNG", "JPEG"]}
	itemComponent={props => (
		<S.Item item={props.item}>
			<S.ItemLabel>{props.item.rawValue}</S.ItemLabel>
		</S.Item>
	)}
>
	<S.Label>Format</S.Label>
	<S.Trigger>
		<S.Value<string>>{state => state.selectedOption()}</S.Value>
	</S.Trigger>
	<S.Portal>
		<S.Content>
			<S.Listbox />
		</S.Content>
	</S.Portal>
</S.Root>
```

The anatomy table lists the styled elements. Set `size` and `theme` on `Trigger`. Set the same `size` on `Root` to size the label and messages. Use `Portal` to mount the list and `Section` to render option groups. To submit selected keys with a form, put `FormValue` inside `Root` with the field `name` and the same `disabled` state.

## Accessibility

### Keyboard

| Key | Action |
| --- | --- |
| Tab or Shift+Tab | Moves focus to or away from the trigger. |
| Enter, Space, or ArrowDown | Opens the list and highlights the selected option, or the first one. |
| ArrowUp | Opens the list and highlights the selected option, or the last one. |
| A printable character | Moves to the next option whose text starts with the typed characters. |
| ArrowDown or ArrowUp in the list | Moves the highlight. Disabled options are skipped. |
| Home or End in the list | Moves the highlight to the first or last option. |
| Enter or Space in the list | Selects the highlighted option. In single mode, the list closes. |
| Escape | Closes the list and keeps the value. |

### ARIA

The trigger is a `button` with `aria-haspopup="listbox"` and `aria-expanded`. Its name comes from the visible `label`. Pass `aria-label` only when there is no visible label. The list is a `listbox`, and each item is an `option` with `aria-selected`. Disabled options have `aria-disabled="true"`. `description` and `errorMessage` are linked to the trigger with `aria-describedby`.

### Focus

When the list opens, focus moves into it, onto the selected option or the first one. When it closes, by selection or by Escape, focus returns to the trigger. The trigger draws its focus ring from `--cui-focus-color`.

## SSR notes

The label, the trigger with the selected value, and the messages render on the server. The list renders in a portal only on the client, after the user opens it. Kobalte generates the ids that link the label and the messages, and they match between the server and the client. Keep `options` and `value` equal on both sides to avoid a hydration mismatch in the trigger text.

## Theming hooks

The trigger uses the shared field styles. The list uses the menu surfaces.

- `--cui-surface-input`, `--cui-text-input`, `--cui-border-input`, and `--cui-text-hint` for the trigger and its placeholder.
- `--cui-text-danger` for the invalid border and the error message.
- `--cui-surface-dialog` for the disabled fill.
- `--cui-focus-color` for the focus ring.
- `--cui-border-width` and `--cui-border-width-strong`, the second for the `inline` theme.
- `--cui-control-height-{xs,sm,md,lg}`, `--cui-font-size-{xs,sm,md,lg}`, and `--cui-radius-{xs,sm,md,lg,xl}` for sizes.
- `--cui-surface-menu`, `--cui-border-menu`, `--cui-shadow-menu`, and `--cui-text-menu` for the list.
- `--cui-surface-menu-hover` for the highlighted option.
- `--cui-space-{1,2,3}`, `--cui-font-weight-normal`, and `--cui-control-height-md` for list items.
- `--cui-motion-duration-{fast,normal}` and `--cui-motion-ease-out` for the list's Pop: in from `scale(0.96)` over 160ms and out to `scale(0.98)` over 120ms, from the trigger side. Opened from the keyboard, the list appears in place (`data-motion="none"`).

Each brace expands to a separate variable. See [Inkstone color](/docs/design/color) and [motion](/docs/design/motion).
