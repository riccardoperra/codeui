## When to use

Use Skeleton where a snippet preview or metadata will appear. Matching the loaded content dimensions keeps the layout steady.

## When to choose another component

Use [Spinner](/docs/components/spinner) for a compact busy indicator inside a control. Use [Progress](/docs/components/progress) for a task with a measurable value.

## Variants

### Shapes and dimensions

<SolidDemo name="skeleton/shapes" />

`width`, `height`, and `radius` accept CSS values. Width defaults to `100%` and height to `auto`. A circle uses height for width, falling back to width.

### Animation

<SolidDemo name="skeleton/animation" />

`animate` defaults to true. Set it to false for a static placeholder. Reduced motion also disables the pulse.

## States

<SolidDemo name="skeleton/revealed" />

`visible` defaults to true. Set it to false when content is ready. The children remain mounted while the placeholder is visible.

Styled Kobalte Skeleton root. It hides the visible placeholder from assistive technology. Its inherited dimensions use numeric pixel values; the ready Skeleton accepts CSS values.

## Styles export

### `skeletonStyles`

`skeletonStyles` is typed as `SkeletonStyles`. Each part function returns a class string. Use it when you own the markup and semantics. `root({ circle, animate })` selects the shape and pulse. Styles alone do not provide visibility attributes or hide content from screen readers.

## Accessibility

### Keyboard

Skeleton is non-interactive and has no keyboard commands. It does not add a tab stop.

### ARIA

Kobalte Root renders `role="group"`. While `visible` is true, Root has `aria-hidden="true"`. When `visible={false}`, the kit removes that attribute and reveals the children. The loading region owns `aria-busy`; Skeleton does not add it. Hidden placeholder content is not an announcement.

### Focus

Mounting or removing the component does not move focus. There is no open or close focus cycle. The reveal example keeps its toggle outside the loading region so focus stays available.

### Reduced motion

Visible placeholders pulse when `animate` is true. Under `prefers-reduced-motion: reduce`, the pulse stops and the shape stays visible. Visibility and ARIA behavior stay the same.

## SSR notes

The component renders inline on the server. It has no portal or client-only effect. Use the same initial props on the server and client. The server renders the placeholder or revealed content from `visible`. CSS handles the pulse and reduced motion.

## Theming hooks

The component reads these theme variables.

- `--cui-action-neutral-base`
- `--cui-motion-duration-slow`
- `--cui-motion-ease-out`
- `--cui-radius-full`
- `--cui-radius-xs`

Defaults come from the kit theme. See [Color](/docs/design/color), [Typography](/docs/design/typography), [Space and shape](/docs/design/space-and-shape), and [Motion](/docs/design/motion).

## Composition examples

The demo under [States](#states) composes Skeleton with a loading region. The button toggles `visible` and the loading region's `aria-busy` together. The title becomes accessible when the placeholder disappears. Keep interactive controls outside hidden loading content.
