## When to use

Turn a setting on or off immediately, such as line numbers in the editor preview.

## When to choose another component

Use [Checkbox](/docs/components/checkbox) for agreement or independent options submitted together. Switch has no indeterminate state.

## Styles export

### `switchStyles`

`switchStyles` maps each part name to a function that returns its kit class string. Functions accept `SwitchVariants`. Use the functions on custom markup when you already own its behavior. They do not add ARIA or keyboard handling. `SwitchStyles` types the map. `SwitchParts` exposes the styled components as a namespace.

## Accessibility

### Keyboard

| Key   | Action                    |
| ----- | ------------------------- |
| Tab   | Focus the control.        |
| Space | Toggle the checked state. |

### ARIA

The input exposes `role="switch"` and `aria-checked`. Description and error components associate hint text with the field. `validationState="invalid"` exposes invalid state. Supply a visible label or an accessible name.

### Focus

These controls do not open an overlay or move focus on mount. Disabled controls cannot receive keyboard focus. Read-only controls remain focusable and do not change value.

## SSR notes

The root, labels, controls, and form inputs render on the server. No part uses a portal. Keep initial values and component order stable between server and client so generated IDs hydrate consistently. Create signals per component instance.
