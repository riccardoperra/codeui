## When to use

Use a hover card to preview what sits behind a link: a file, a person, a thread. Use it for a description or for more than one fact. A single name belongs in a [Tooltip](/docs/components/tooltip), and the `title` attribute is never the answer.
It opens when the pointer rests on the trigger, when the trigger gets keyboard focus, and on click, so it works on touch screens. It closes when the pointer leaves both, on blur, on Escape and on a press outside.

A hover card is supplementary. Never put the only path to an action or to information inside it. The card never takes focus, so a keyboard user cannot reach a button inside it. Keep the same details reachable from the page the link opens.

## When to choose another component

- [Tooltip](/docs/components/tooltip) names a control in a few words. A hover card holds a few lines of rich content.
- [Popover](/docs/components/popover) opens on click, takes focus, and can hold buttons and fields. Use it when the user has to act on the content.

## Variants

### Placement

<SolidDemo name="hover-card/placements" />

`placement` sets the side and the alignment. The default is `right-start`: the card sits beside its trigger, top edges aligned, so it does not cover the lines below. When there is no room on the right, Kobalte flips it to the left. The card wraps its text at 20rem (320px).
`gutter` sets the distance from the trigger. The kit sets it to 6px.

### Delays

<SolidDemo name="hover-card/delays" />

The card opens 500ms after the pointer enters or the trigger gets focus, and closes 150ms after the pointer leaves the trigger and the card. Change this with `openDelay` and `closeDelay`.
On its way from the trigger to the card, the pointer may cross the gap between them without closing the card. `ignoreSafeArea` turns that off.

### List of entries

<SolidDemo name="hover-card/list" />

Use `HoverCardList` and `HoverCardItem` to list tasks, files or members. Each entry is one line: a state icon, a short identifier, then the title, truncated. Show nesting with `depth`, which indents the entry 16px per level, not with tree lines. Drop a prefix every entry shares. A finished entry shows no icon, and the icon slot stays so the identifiers line up.

The list caps at 24rem (`--cui-hovercard-list-max-height`) and scrolls on its own, so the card keeps its size. The list takes focus with Tab once the card is open, so a keyboard user can scroll it.

Give each state icon a name with `iconLabel`, such as "Running", and make each state differ in shape, not only colour.

## States

### Opened by click or tap

A click opens the card at once, without `openDelay`. On a touch screen, the first tap on a closed card opens it and does not follow the link; the next tap follows it. A press outside closes the card.

### Controlled

Without `open`, the card manages its own state. To control it, pass `open` and `onOpenChange`.

## Accessibility

### Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moving focus to the trigger opens the card after `openDelay`. Moving focus away closes it. |
| <kbd>Enter</kbd> | Follows the link. A trigger rendered as a button opens the card. |
| <kbd>Escape</kbd> | Closes the card. Focus stays on the trigger. |

### ARIA

- A `HoverCardList` is a list with its `aria-label`; a named state icon is an image with its state name.
- The card has no role and is not linked to the trigger. Screen readers announce the link only, which is why the card must not hold anything the user needs.
- Escape closes the innermost layer only, so a hover card inside a dialog closes before the dialog.

### Focus

The card never takes focus. Focus stays on the trigger while it is open.

## SSR notes

The trigger renders on the server. The card renders on the client, and only while it is open.

## Theming hooks

`HoverCardContent` reads these variables. Set the `--cui-hovercard-content-*` ones on the card to change a single card. See [Tokens](/docs/foundations/tokens) for the defaults.

| Variable | Default | Used for |
| --- | --- | --- |
| `--cui-hovercard-content-background` | `--cui-surface-dialog` | Fill |
| `--cui-hovercard-content-box-shadow` | `--cui-shadow-dialog` | Shadow, and the 1px ring in dark mode |
| `--cui-hovercard-content-radius` | `--cui-radius-card` | Radius (16px) |
| `--cui-hovercard-content-padding` | `--cui-space-4` | Padding |
| `--cui-hovercard-content-max-width` | `min(320px, 100vw - 32px)` | Width limit |
| `--cui-hovercard-content-font-size`, `--cui-hovercard-content-line-height` | `--cui-font-size-sm`, `--cui-font-line-height-snug` | Text (14px / 1.3) |
| `--cui-hovercard-content-color` | `--cui-text-dialog` | Text colour |
| `--cui-hovercard-list-max-height` | `24rem` | Height of a list before it scrolls |
| `--cui-hovercard-item-indent` | `16px` | Indent per `depth` level |
| `--cui-hovercard-item-depth` | Set from `depth` | Nesting level of one entry |
| `--cui-motion-duration-normal`, `--cui-motion-duration-fast`, `--cui-motion-ease-out` | | Pop: in from `scale(0.96)` over 160ms, out to `scale(0.98)` over 120ms |

A card opened by hover or click pops from the trigger side, with `transform-origin` from `--cui-popper-content-transform-origin`. A card opened by keyboard focus appears with no animation (`data-motion="none"`). With reduced motion, the card only fades.
