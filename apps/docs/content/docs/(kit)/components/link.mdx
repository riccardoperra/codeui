## When to use

Use `Link` for navigation in text, such as a reference to a snippet or the source repository.

## When to choose another component

Use [Button](/docs/components/button) for an action or prominent navigation styled as a button. Use [IconButton](/docs/components/icon-button) for a compact icon action with a tooltip.

## Variants

<SolidDemo name="link/variants" />

The default has no underline. `variant="underline"` adds an underline on hover only. There are no theme, size, pill, loading, or icon-slot props. Place decorative icons in the children.

## States

### Disabled

<SolidDemo name="link/disabled" />

`disabled` prevents activation and removes the control from the tab order. Kobalte removes the destination from a disabled anchor and sets `aria-disabled`.

## Accessibility

### Keyboard

| Key | Action |
| --- | --- |
| Tab or Shift+Tab | Moves focus between enabled controls. |
| Enter | Follows the focused link. |

### ARIA

The anchor with `href` has native link semantics. Disabled links expose `aria-disabled` and `data-disabled`.
The visible text supplies the accessible name. Hide decorative icons from assistive technology.
Choose link text that describes the destination. Include new-tab behavior in the label when relevant.

### Focus

The kit Link styles remove the outline and do not add a focus-visible ring. Supply a visible focus style in your app until the kit fixes this gap.
These controls do not open an overlay or move focus on their own. If your handler opens or closes an overlay, that overlay owns focus placement and restoration.

## SSR notes

The root and its children render on the server. There is no portal or client-only mount step in `Link`.
Event handlers become active after hydration. Keep the initial props equal on the server and client.


## Theming hooks

`Link.css.ts` reads no `--cui-*` variables. It inherits color and line height. Override its `class` for app-specific text and focus styles.
