## When to use

Use a popover to pick a value for one row or to show short, interactive content next to the control that opened it.
It has no scrim and does not block the page. Focus moves into the panel and returns to the trigger on close.

## When to choose another component

- [Tooltip](/docs/components/tooltip) names a control. It holds text only and cannot take focus.
- [DropdownMenu](/docs/components/dropdown-menu) lists actions. Use it when each row runs a command.
- [Dialog](/docs/components/dialog) holds settings or a decision that blocks the page.
- [Select](/docs/components/select) picks one value from a list known by name.

## Variants

### Bordered

<SolidDemo name="popover/bordered" />

`variant="bordered"` adds a 1px border in `--cui-border-menu`. Use it when the panel sits on a surface of the same color.

### Placement

<SolidDemo name="popover/placements" />

`placement` on `Popover` sets the side and the alignment: `top`, `right`, `bottom`, or `left`, each with an optional `-start` or `-end`. The default is `bottom`.
When the panel does not fit, Kobalte flips it to the opposite side.

### Gutter and shift

<SolidDemo name="popover/gutter" />

`gutter` is the distance between the trigger and the panel. The kit sets it to 6px. `shift` moves the panel along the trigger edge.

### Rich title and block content

<SolidDemo name="popover/rich-content" />

`title` takes JSX, so it can carry a badge. The title names the panel through `aria-labelledby`.
Children render directly in the content, without a `p` wrapper. So a grid of buttons or a form is valid HTML inside the panel.
`description` renders in a `p` element. Keep it to inline content and put blocks in the children.

### Anchor

<SolidDemo name="popover/anchor" />

The `Anchor` part lines the panel up with an element other than the trigger, such as the whole settings row. The trigger still opens the panel and gets focus back on close.

## States

### Open, controlled, and uncontrolled

Without `open`, the popover manages its own state. Set `defaultOpen` to open it on first render.
To control it, pass `open` and `onOpenChange` to `Popover`.

### Modal

`modal` is `false` by default, so the rest of the page stays interactive and focus can leave the panel. Moving focus or clicking outside closes it.
Set `modal` to trap focus inside the panel and hide the rest of the page from assistive technology.

## Styles export

### `popoverStyles`

`popoverStyles` from `@codeui/kit/popover` maps each part name to a function that returns its class string.
Call `popoverStyles.content()` for the class and set `data-variant="bordered"` on custom content. `trigger()`, `anchor()`, `arrow()`, and `closeButton()` return empty strings.

Call a style function when you render the Kobalte primitive yourself and want the kit look. Add the matching `data-cui` value from `popoverParts` too.
[Compose styled parts](/docs/patterns/compose-styled-parts#kobalte-with-kit-classes) shows a full example.

The root package `@codeui/kit` also exports a `popoverStyles`, with a different shape. It is the raw style module: `content()` returns the base classes and `title` and `description` are class strings. Prefer the subpath export.

## Accessibility

### Keyboard

| Key | Action |
| --- | --- |
| <kbd>Enter</kbd>, <kbd>Space</kbd> | On the trigger, opens or closes the panel. |
| <kbd>Tab</kbd> | Moves focus through the panel. Moving focus out of a non-modal panel closes it. |
| <kbd>Escape</kbd> | Closes the panel and returns focus to the trigger. |

### ARIA

- The panel has `role="dialog"`. Kobalte links it to `Title` with `aria-labelledby` and to `Description` with `aria-describedby`.
- The trigger has `aria-haspopup="dialog"`, `aria-expanded`, and `aria-controls`.
- Without a title, give the panel an accessible name with `aria-label` on `PopoverContent`.
- The close button's accessible name is `close`. Change it with `aria-label`.

### Focus

On open, focus moves to the first focusable element in the panel, or to the panel itself. On close, focus returns to the trigger.

## SSR notes

An open or force-mounted popover includes its panel in server HTML at the Portal declaration. Hydration adopts the existing nodes and moves them to `mount`, or `document.body` by default. Closed content stays absent unless force-mounted. Place Portal in a flow-content context that can contain the panel markup.
The trigger and the anchor render on the server. Their IDs come from Solid's `createUniqueId`, so they match after hydration.

## Theming hooks

`Popover` reads these `--cui-*` variables. See [Tokens](/docs/foundations/tokens) for the defaults.

| Variable | Used for |
| --- | --- |
| `--cui-surface-dialog` | Panel fill, the floating surface CodeImage uses |
| `--cui-shadow-dialog` | Panel shadow, with a 1px inset ring in dark |
| `--cui-border-menu`, `--cui-border-width` | Border of the `bordered` variant |
| `--cui-text-dialog`, `--cui-text-dialog-title` | Description and title text |
| `--cui-radius-xl` | Panel radius (18px) |
| `--cui-space-4` | Panel padding, and the phone gutter of the width |
| `--cui-space-2` | Gap between title, description, and children |
| `--cui-font-size-sm`, `--cui-font-line-height-snug` | Body and description type (14px / 1.3) |
| `--cui-font-size-md`, `--cui-font-weight-semibold` | Title type (16px) |
| `--cui-motion-duration-normal`, `--cui-motion-duration-fast`, `--cui-motion-ease-out` | Pop: in from `scale(0.96)` over 160ms, out to `scale(0.98)` over 120ms |

The panel is at most 360px wide, the Inkstone picker width, and never wider than the viewport minus 16px on each side. That value is a literal in the kit, not a token.

### Motion

A popover opened with a pointer pops: it fades in from `scale(0.96)` over 160ms and leaves toward `scale(0.98)` in 120ms, growing from the trigger side (`--kb-popper-content-transform-origin`). Opened from the keyboard, the content gets `data-motion="none"` and appears and leaves in place. With reduced motion, only the fade is left.
