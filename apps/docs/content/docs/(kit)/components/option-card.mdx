## When to use

Use option cards for a single choice where a preview helps you compare options, such as colour mode, navigation, or snippet themes.

## When to choose another component

Use [SegmentedControl](/docs/components/segmented-control) for short text choices. Use [Switch](/docs/components/switch) for an independent boolean. Use [Select](/docs/components/select) for a long list of names.

`OptionCardGroup` renders the group label, description, error message, and one `OptionCard` per entry. `OptionCard` renders one item and needs a radio-group root. It does not create a group itself.

## Anatomy

| Export | Renders | `classes` key | `data-cui` | Role |
| --- | --- | --- | --- | --- |
| `Root` | div | `root` | `option-card-root` | radiogroup |
| `Label` | span | `label` | `option-card-label` | Group name |
| `Description` | div | `description` | `option-card-description` | Group description |
| `ErrorMessage` | div | `errorMessage` | `option-card-error-message` | Validation message |
| `Item` | div | `item` | `option-card-item` | group |
| `ItemInput` | input | `itemInput` | `option-card-item-input` | Native radio |
| `ItemControl` | div | `itemControl` | `option-card-item-control` | Visual control |
| `ItemIndicator` | div | `itemIndicator` | `option-card-item-indicator` | Selection mark |
| `ItemLabel` | label | `itemLabel` | `option-card-item-label` | Input label |
| `ItemDescription` | div; span in ready item | `itemDescription` | `option-card-item-description` | Input description |
| `Preview` | div | `preview` | `option-card-preview` | Decorative |
| `Badge` | span | `badge` | `option-card-badge` | Status text |

The ready item renders `ItemInput` and `ItemLabel`. It does not render `ItemControl` or `ItemIndicator`. Preview, badge, and description render only when supplied. The label is the card title.

## Variants

### Card and tile

<SolidDemo name="option-card/themes" />

`card` is the default. `tile` reduces label padding. Previews are noninteractive, decorative areas above the title. Keep the choice understandable from its label alone. The `Default` badge is supplied content, independent of selection.

### Grid and column

<SolidDemo name="option-card/vertical" />

The horizontal root uses an auto-fit grid with a 128px minimum column width, capped at the container width. Vertical orientation uses one column. Orientation also controls arrow-key navigation.

## States

### Selected and controlled

<SolidDemo name="option-card/controlled" />

Use `defaultValue` for an initial selection or `value` with `onChange` for a controlled selection. `OptionCardEntry<T>` keeps values and the callback in the same string union. `createOptionCardItems` wraps an items accessor as `{ items }` without changing entries.

The selected label gets an accent border. Keyboard focus has a separate outline. Inkstone specifies a selected fill step and an inset accent outline. The current kit uses the same resting fill and a transparent border that becomes accent when checked.

### Disabled

<SolidDemo name="option-card/disabled" />

An entry can disable one card. Group `disabled` disables all entries. `readOnly` prevents value changes without the disabled appearance.

### Read-only

<SolidDemo name="option-card/read-only" />

The managed value remains focusable, but user input cannot change it.

### Required and invalid

<SolidDemo name="option-card/invalid" />

`required` enables native form validation. `validationState="invalid"` exposes the invalid state and displays `errorMessage`. The invalid border replaces the selected accent border.

### Long labels

<SolidDemo name="option-card/long-labels" />

Labels and descriptions wrap, including unbroken text. Cards stretch across each grid row. Keep previews at a consistent height so titles align. Do not truncate labels.

## Styles export

### `optionCardStyles`

`optionCardStyles` is exported from `@codeui/kit` and `@codeui/kit/option-card`. Each anatomy key is a function that returns a class string. `OptionCardStyles` describes those functions. `OptionCardPart` is the key union, and `OptionCardClasses` is a partial map of keys to class names.

Functions accept `OptionCardVariants`, but currently ignore that argument. Tile padding depends on `data-variant="tile"`, and the single-column layout depends on `data-orientation="vertical"`. Use styled parts to set those attributes. A class string alone does not supply radio semantics or state attributes.

## Accessibility

### Keyboard

| Key | Action |
| --- | --- |
| Tab | Enters the group once, at the selected enabled radio or the first enabled radio. The next Tab leaves. |
| Shift+Tab | Moves to the previous tab stop. |
| Right or Left arrow | Moves focus and selects the next or previous enabled option in horizontal orientation. |
| Down or Up arrow | Moves focus and selects the next or previous enabled option in vertical orientation. |
| Space | Selects the focused radio. |

### ARIA

The root renders `role="radiogroup"` with its label and description connected through ARIA IDs. The item container renders `role="group"`. Its visually hidden native `input type="radio"` exposes selection, disabled, required, and invalid state. Group validation uses `aria-invalid`, `aria-required`, and `aria-disabled`. An invalid error message joins the description IDs. Preview content is hidden from assistive technology.

### Focus

Focus stays on the native input and shows an outline around its card. Selection moves focus within the group. Cards open no overlay and have no open or close focus behavior.

## SSR notes

The group, inputs, labels, and supplied content render on the server. There is no portal or client-only preview. Keep item values, order, and initial selection identical during hydration. Create controlled state inside the component instance so requests do not share it.

## Theming hooks

The card reads `--cui-font-family-sans`, `--cui-font-size-sm`, `--cui-font-size-xs`, `--cui-text-default`, `--cui-text-muted`, and `--cui-text-hint`. Errors read `--cui-text-danger` and `--cui-action-danger-base`.

Surfaces use `--cui-surface-input` and `--cui-surface-input-accent`. Selection uses `--cui-action-brand-base`; focus uses `--cui-focus-width`, `--cui-focus-color`, and `--cui-focus-offset`. Shape uses `--cui-radius-md`. Spacing reads `--cui-space-2`, `--cui-space-3`, `--cui-space-8`, `--cui-space-10`, `--cui-space-16`, and `--cui-space-32`. The preview currently has a 64px minimum height; Inkstone specifies 68px.

The optional badge uses the [Badge theming hooks](/docs/components/badge). Token defaults are described in [Inkstone colour](/docs/design/color) and [space and shape](/docs/design/space-and-shape).
