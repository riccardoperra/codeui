## Colour palette

Light and Dark use one grey ramp. Blue has a separate ramp for actions and focus. Components use the CSS tokens in **Theme roles**. The numbered steps are for theme authors.

<ColourPalette />

### Use colours by role

- **Build the surface hierarchy.** Use `--cui-surface-panel` for the page, `--cui-surface-canvas` inside it, and `--cui-surface-input` for fields and tiles on the island. Use `--cui-surface-dialog` for floating UI.
- **Pair the surface with its text.** Use `--cui-text-default` for titles and values. Use `--cui-text-muted` for descriptions and metadata.
- **Keep selected rows neutral.** Use `--cui-surface-field-hover` and primary text. For a selected card, add an accent ring as well as the fill change.
- **Reserve a filled accent for one primary action per surface.** Pair `--cui-action-brand-base` with `--cui-action-brand-text`. Use `--cui-focus-color` for keyboard focus.
- **Use status colours for feedback.** Use `--cui-action-danger-base` for destructive confirmation, `--cui-action-caution-base` for risk, and `--cui-action-success-base` for a positive outcome. Pair status colour with a label or icon.
- **Check new colour pairs in both themes.** Use at least 4.5:1 for normal text and 3:1 for large text, focus rings, and visual cues needed to identify controls or states.
- **Keep raw colours in theme definitions and swatch references.** Use `var(--cui-…)` in component styles so a theme change reaches the component.

### Apply the tokens in CSS

This example uses a neutral selection for an export format and a single filled export action. Use the appropriate selection semantics for the control and include a visible selected indicator.

```css
.export-island {
	background-color: var(--cui-surface-canvas);
	color: var(--cui-text-default);
}

.export-format[aria-selected="true"] {
	background-color: var(--cui-surface-field-hover);
	color: var(--cui-text-default);
}

.export-action {
	background-color: var(--cui-action-brand-base);
	color: var(--cui-action-brand-text);
}

.export-action:focus-visible {
	outline: var(--cui-focus-width) solid var(--cui-focus-color);
	outline-offset: var(--cui-focus-offset);
}
```

### Generate the palette and theme tokens

Gosfuig generates the ramps from `packages/inkstone/tokens/inkstone.palette.json`. The Inkstone build writes `palette.tokens.json`, then Toghen resolves the semantic aliases for each mode. The resulting `@codeui/inkstone/theme.css` is the default theme in the Solid kit. [Gosfuig](https://codeberg.org/Toghen/gosfuig)

Use `@codeui/inkstone/resolver.json` to work with the original DTCG data, or import `@codeui/inkstone/light.json` or `@codeui/inkstone/dark.json` for resolved roles. The DTCG colours contain OKLCH components and an sRGB hex value. The CSS theme uses the sRGB values and adds relative colour formulas for states that follow the brand base.

Fumadocs projects the same ramps into its `--color-fd-*` tokens. To inspect the ramp JSON in the repository, run `pnpm --silent palette:generate`.

## Surfaces are carved

<FigSurfaces n={1} caption={<><b>Five surfaces, no borders.</b> Each level sits on the one below it. Only the floating menu has a shadow, because only it floats.</>} />

The dark page uses `#1c1c1c`. Its islands use `#111111`. An open section uses the page colour, and a field uses `#292929`.

This came from reviewing CodeImage's editor. A compact build with bordered panels was rejected because it felt fragmented. The maintainer asked for "un layout più unito e a isole", a more unified layout made of islands. Fill steps group controls without adding lines, and lines would compete with the user's content for attention.

Each surface sits only on the level directly below it. A field goes inside an island, not straight on the page.

### State is a step of fill

Hover raises an element's fill by one step. A selected item is also one step up. A pressed element changes its fill but keeps the same shape as when hovered. There is no underline, no thicker border and no glow.

One case needs more than fill. A selected card must differ from its island by its fill **and** an accent ring. In CodeImage's light mode, a card on a grey island could only be told apart by its ring, so cards had to be lifted to white.

### A known weakness

The page and an island differ by about 1.1:1. On a dim or cheap screen an island can almost vanish. The layout still holds because islands are also defined by their rounded shape and their position. For the same reason, never rely on a change of fill alone to show that something can be clicked.

### The token names are inverted

The kit's tokens were named before the carved layout existed. `--cui-surface-canvas` is the island, and `--cui-surface-panel` is the page. Until they are renamed, go by the table in `DESIGN.md` §2.1, not by the token names. The proposed names are `surface-page`, `surface-island`, `surface-field` and `surface-floating`.

## Text has two working tones

Descriptions, summaries, hints and unselected navigation use `--cui-text-muted`. Use `--cui-text-default` for titles, values the user set and selected items.

This is what keeps the screen calm. A panel full of bright labels looks busy even when it has few controls. Visual weight comes from tone first, then from weight, and only then from size.

Use tertiary text for captions on the page, an island or a field. Keep the disabled tone for controls that are unavailable.

## Light mode is one grey family

Both modes use the 16-step achromatic ramp shown above. The light page uses `gray.100`, the island uses `gray.150`, and the field uses `gray.250`. In dark mode those roles use `gray.900`, `gray.950`, and `gray.750`.

The switch off track uses `gray.550` in light mode and `gray.650` in dark mode. The thumb position also indicates the state where the track has less than 3:1 contrast against its surface.

## One accent, five jobs

| Job | Shape |
| --- | --- |
| Keyboard focus | A 2px ring with a 2px offset |
| The selected card | A 2px ring |
| On or active | A switch track, the icon of the open section, a check, a 15% wash |
| New or unread | A 6–7px dot |
| The one primary action | A filled button |

Blue appears rarely, so users notice it when it does.

- **One filled accent button per surface.** If two actions both seem primary, one of them is not.
- **Selected rows stay neutral.** In a list, menu, command menu or settings navigation, the selected row gets the field fill and primary text. An accent fill on every selected row would put blue all over the screen, and it would no longer stand out where it matters.
- **"On" and "do" look different.** CodeImage once had a blue Play button next to a pressed, blue Animate button, and the two read as one control. Use the soft wash for "on" and the filled button for "do".

### One brand blue for every fill

The shared brand fill is `#0076cf` in both themes. Hover uses `#0068b9` and active uses `#004f8e`. White labels reach 4.7:1, 5.7:1, and 8.4:1 in those states.

The focus ring uses `--cui-accent-focus`, `#63b3ed` in dark mode and `#0068b9` in light mode. Links and labels on the 15% wash use `--cui-action-brand-soft-text`, `#63b3ed` in dark mode and `#004f8e` in light mode.

The hover, active, soft, focus and selection colours follow `--cui-action-brand-base` through CSS relative colours. If you override the base, check contrast across the states.

## Status colours

Danger, caution and success mark states the user must notice: an error, a destructive confirmation, a failed export. They do not decorate anything and are not used to label categories. Danger fills only the confirm button of a destructive dialog, and an error always pairs its colour with an icon.

Each status has one source colour, its `base`. Hover and active are computed from it with the same steps the Inkstone values use, so a theme that changes the base keeps the states in proportion.

## Lines

A line is allowed only where a fill would disappear:

1. **The inner ring of a floating surface in dark mode.** A shadow does not show on a near-black page, so a 1px ring traces the edge instead.
2. **Focus and selection rings.**
3. **A ring around a colour swatch, orb or avatar** whose colour could match the background. Use a neutral grey at 16–35% opacity.

A split button such as Export is still a single control. Its two parts are separated by a 2px gap and 4px inner corners, not by a border.
